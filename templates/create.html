How it works

Store the key, not the message

Most secret-sharing services keep your encrypted message and promise to delete it. KeyBank inverts that: the encrypted message lives in the link you share, and the server keeps only a single-use key.

  1. KeyBank mints a key pair

    Your browser asks for a fresh RSA-4096 key pair. KeyBank stores the private half and hands back the public half. All it learns is how long to keep the key.

  2. Your browser seals the note

    The note is encrypted with a random AES-256-GCM key, which is in turn locked with the public key. Both go into the link after the #, the part a browser never sends to a server.

  3. The key is used once, then gone

    Opening the link fetches the private key, and KeyBank deletes it in the same atomic step. The recipient’s browser decrypts the note locally, and the link never works again.

A typical secret-sharing service

  • Keeps your encrypted message on its disk until it is read or expires.
  • Asks you to trust that it really deletes the message.
  • Handles notes of any length.

KeyBank

  • Never receives your message, not even encrypted. A stolen key is useless without the link.
  • Reading the note is what deletes the key: fetch and delete are one step.
  • The note travels inside the link, so it is best for short secrets.
